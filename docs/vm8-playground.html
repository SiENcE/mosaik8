The core follows vm8-spec.md instruction-exactly: 8 threads × QUANT budget, u16 PC behind a fetch seam, waitables by PC rewind, cutscene lock + exempt music context, RAISE exceptions (RESET / CHANGE_SCENE), HANDLE joins, THREADN args, guarded stacks and i16 RPN with the bitwise group. Playground dialect: .string <id> "TEXT" defines the string table ($0$…$127$ interpolates heap vars in text boxes), .board switches the screen to the board renderer (heap rows 0..19 as a 10-wide well), and CHANGE_SCENE room, x, y assembles as sugar for RAISE 2, room, x, y.

QUANT: the spec minimum 16 is sized for real sm83/65C02 hosts; §14 lets a build raise it. Snake is correct at 16: one thread owns every game-state write, so a step that needs more than one slice simply finishes on the next frame. The Snake source is the engine's own sample, projects/vm-snake/scripts/snake.v8s, which that project builds into a ROM.

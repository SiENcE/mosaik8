# Shardlings - how the game was made

What is specific to THIS game: how its art, music and text are produced, the
numbers its rooms and scripts depend on, and the traps it ran into. How the
engine itself works is documented elsewhere; this file only says what you need
to change Shardlings without breaking it.

## The game in one table

| Room | Index | Size (tiles) | Tileset | Song |
| --- | :-: | --- | --- | --- |
| title | 0 | 20x18 | `tiles_title.png` | 0 title |
| tessel (the town) | 1 | 40x18 | `tiles_tessel.png` | 1 town |
| mossway (the route) | 2 | 40x32 | `tiles_mossway.png` | 2 route |
| battle | 3 | 20x18 | `tiles_battle.png` | 3 battle, 8 rival (Wren), 4 victory |
| home | 4 | 20x18 | `tiles_home.png` | 5 home |
| elder_house | 5 | 20x18 | `tiles_elder_house.png` | 6 elder |
| shop | 6 | 20x18 | `tiles_shop.png` | 7 shop |

The interiors are appended AFTER battle on purpose: scripts address rooms by
index (`change_scene room = N`, `scene() == N`), so a room inserted in the
middle would renumber every one of them.

Flow: title -> home (Mom) -> Tessel -> the Elder's house (pick a starter) ->
north exit -> Mossway (tall grass, Wren spots you on the path) -> battles.
Losing a battle sends you home (`home_room` / `home_x` / `home_y` in `main`).

## How the files are produced

Most of the project is GENERATED by three small Python scripts kept with the
studio (`tools/gen_samples/`). Edit the script, re-run it, never hand-edit what
it owns:

| Script | Owns |
| --- | --- |
| `shardlings_town.py` | `tiles_tessel.png`, `tiles_home/elder_house/shop.png`, the rock + sign tiles in `tiles_mossway.png`, `anim_water.png`, `mom` / `clerk` / `emote_exclaim` sheets, in `world.toml` the tessel + interior scenes, every door, the two triggers it owns and the palettes below, plus the sprite list / kind entries / `code_banks` additions |
| `shardlings_ui.py` (called by the above) | `font.png`, `frame.png`, `src/uiframe.mos` |
| `shardlings_music.py` | `scripts/songs.toml`, `scripts/instruments.toml` |

Hand-authored and safe to edit in the studio: `scripts/field.evt.toml`,
`scripts/battle.evt.toml`, `scripts/dialogue.toml`, `src/main.mos` (the shell,
which draws the text frame), and everything in `world.toml` the town script
does not own (title, mossway map, battle, kinds, monsters).

Order after a change: run `shardlings_town.py` (it regenerates `scenes`,
`scripts`, `rooms`, `glue`, `clips`, `emotes`), then `shardlings_music.py`,
then regenerate `songs` / `instruments`. `shardlings_town.py --preview DIR`
renders every room to PNG and writes nothing - look before you write.

## Graphics

### Drawn as one picture, cut into tiles

Each room is drawn as ONE pixel canvas: ASCII-art stamps for the props (trees,
windows, doors, furniture, signs) and small procedures for the rest (shingle /
tiled roofs, siding, rounded paths, the pond). The canvas is then cut into 8x8
cells and identical cells (same pixels AND same palette slot) are merged into
one tile. That is why the art can be free-form at pixel level: any shape works,
as long as every 8x8 cell uses one palette.

Stamp characters are shades: `.` 0 lightest, `,` 1, `x` 2, `#` 3 darkest,
space = keep what is underneath.

### Step 1: lay the room out on the tile grid

Every room was planned as a grid of 8x8 cells before any pixel was drawn,
with the player's 16x16 box in mind (paths at least 2 cells wide, doorways
reachable). Tessel, 40x18 cells, x / y in cells:

| What | Cells |
| --- | --- |
| Forest border | trees every 2 cells along row 0 and row 16, columns 0 and 38; the north gap is columns 18..21 |
| Roads | north road 18..21 x 0..1 widening into 18..19 x 0..11; main street 3..36 x 10..11; door spurs 6..7, 13..14 and 26..27 on row 9 |
| Player's home (red roof) | 3..10 x 3..8 (8x6), roof 3 rows, door at columns 6..7 |
| Shop (blue roof, SHOP sign) | 11..16 x 4..8 (6x5), roof 2 rows, door at columns 13..14 |
| Elder's house (green roof, dormer, chimney) | 22..31 x 2..8 (10x7), roof 4 rows, door at columns 26..27 |
| Trees beside the houses | 33..34 x 2..3, 35..36 x 3..4 |
| Mailbox / signs | mailbox 2 x 7..8; signs 16..17 x 2..3 (beside, not on, the north road) and 14..15 x 12..13 |
| Fenced flower garden | fence 3..12 x 12..15, red flowers inside |
| Pond | 27..35 x 12..15, stone rim, animated water inside |
| Flower strip | 22..25 x 13..14 |

Every house ends on row 8, so every door sits on the same row and the spurs on
row 9 join the main street.

An interior is a 20x18 shell: back wall rows 0..3 (wallpaper with vertical
stripes, a baseboard), floor rows 4..15, a dark wall on columns 0 and 19 and
rows 16..17, and the doormat at columns 9..10 of rows 16..17. Furniture then
goes on the grid, against the back wall or in the room:

| Room | Furniture (cell where its top-left goes) |
| --- | --- |
| home | windows 3,0 and 12,0, clock 9,1, bookshelf 15,1, TV 6,3, plants 1,3 and 1,13, bed 16,9, table 6,8 with chairs 5,9 and 10,9, red rug 7,12 |
| elder_house | four bookshelves 2,1 4,1 14,1 16,1, windows 7,0 and 11,0, keystone pedestal 9,4, desk 2,9 with books, chair 4,11, green rug 7,11, plants 1,13 and 16,13 |
| shop | wall shelves 2,1 (blue) and 12,1 (red), counter 1,7 with a register and a bell, floor shelves 13,8 and 13,12, plant 17,4, checkered floor |

The NPCs were placed last, beside their furniture: Mom next to the table, the
Elder in front of the pedestal, the clerk at the end of the counter (a clerk
BEHIND a counter would be out of talking range).

### Step 2: draw the canvas, back to front

1. **Ground**: the whole canvas is grass (shade 1) in the green palette.
2. **Paths**: the union of the road rectangles is filled pale; then every
   CONVEX corner pixel is removed, twice, which rounds the corners. A fixed
   speckle pattern (two pixels per 8x8 cell) gives it texture.
3. **Grass tufts**: a small "v" in dark green on some cells, only where the
   cell is pure grass, chosen by a hash of the cell position so the pattern
   repeats.
4. **Buildings** (one `house()` call each): first the cells get their
   palettes (roof rows: the roof colour; wall rows: wood), then
   - the walls: pale, ink side lines, light-green siding every 4 rows, a
     stone plinth at the bottom;
   - the roof: an ink outline with rounded top corners (the grass shows
     through them), a pale ridge highlight, shingle courses every 4 rows with
     a tick every 8 pixels (offset by 4 on the next course), an eave line;
     the shop uses a vertical-tile roof instead;
   - the door stamp centred in the bottom two rows, 16-pixel windows on fixed
     cell columns, the SHOP sign or the dormer and chimney;
   - collision for the whole house except the doorway sill, and a 2-pixel
     shadow on the grass below.
5. **Props**: border trees, the two extra trees with shadows, the mailbox,
   the signs, the fence (a horizontal and a vertical fence stamp), the flowers
   and the bushes. Each prop cell gets its palette (wood, red flowers) first.
6. **Pond**: drawn pixel by pixel from the distance to its edge: an ink rim,
   pale stones, an inner ink line, blue water; only the inner cells get the
   wave crests, so they are all ONE tile, the one that animates.

Interiors follow the same order: the shell, then each piece of furniture with
`furniture(x, y, stamp, slot)`, which sets the palette of the cells it covers,
draws it and marks it solid. Tables, the desk and the counter come from a small
`box()` generator (ink outline, pale top, accent front); the bed, shelves,
plant, TV, clock, windows and the pedestal are ASCII stamps.

### Step 3: cut into tiles and write the map

Each 8x8 cell becomes a key of its 64 pixels plus its palette slot. The first
time a key is seen it becomes the next tile; the map stores the tile index per
cell and `tile_palette` stores the slot per tile. The tileset PNG is a strip 8
pixels wide, its palette four greys (index = shade). The tile count is printed
on every run; that number is what the budget above is checked against.

### Step 4: look, fix, repeat

`--preview` renders every room in its real colours. Each room went through
several rounds of looking at the preview, then at the ROM in an emulator (GBC,
and SMS / GG / PCE screenshots), and fixing what showed. Fixes that came out
of it: the shop's windows covered its sign (the shop grew to 6 cells), the
baseboard took each piece of furniture's colour (it is now drawn in shared
shades only), books and the register floated above their furniture, the
town needed fewer tiles (shared walls, aligned windows, periodic textures), a
sign narrowed the north road, and the doorways needed sills.

### Sprites and the font

The two new characters were drawn as 16x16 ASCII grids in the style of the
existing ones: an ink outline, shade 1 = skin, shade 2 = clothes, transparent
background. Mom has long dark hair and a dress; the clerk has a cap and a
pale apron. Each was drawn facing down, up and right. The second walk frame of
a direction is the first with the bottom rows moved by one pixel (a foot
lift).

The font was written glyph by glyph as eight 8-character strings: 2-pixel
vertical strokes, 6 pixels wide (M and W take 7), 7 rows tall, row 8 used only
by the descenders of g, j, p, q and y. The frame is three hand-drawn tiles
(corner, edge, side, all with an ink outer line and an accent inner line),
mirrored into the other six.

### The palette rule that makes it work

Every room palette is **PALE, GROUND, ACCENT, INK**, and three of the four are
SHARED by all palettes of that room:

| Room | 0 (pale) | 1 (ground) | 3 (ink) | Slot 2 accents |
| --- | --- | --- | --- | --- |
| town | `F0F8D0` | grass `78C058` | `102018` | green roof `207020`, red roof `E04830`, blue (shop, pond) `3068D8`, wood `A06838` |
| interiors | `F8F0E0` | floor `E0B870` | `201018` | wood, blue, green, red; in the Elder's house slot 3 is the KEYSTONE |

So grass, path and floor look the same in every palette, and a prop drawn in
any palette sits on the ground with no coloured square around it (the bug the
first town had). A cell switching palette loses its grass tufts (they are
drawn in shade 2, which is the accent elsewhere).

**The colours are chosen for the Master System too.** The SMS rounds every
channel to the nearest of four levels; the first draft's grass and floor both
became olive and its dark green and ink became the same colour. Every colour
above rounds to a distinct SMS colour (grass `55AA55`, dark green `005500`,
ink `000000`, roof `FF5555`, blue `5555FF`, floor `FFAA55`). Check that
rounding before picking a new colour.

### Tile budget (the SMS is the limit)

With `[scenes] glyph_text` the text is drawn into the tiles ABOVE the largest
room tileset, and the SMS / Game Gear background ends at tile 192. The 9-tile
text frame sits directly on the art (`uiframe.BASE` = the largest tileset), so:

- town **135** tiles, each interior about **65** (one tileset PER interior: a
  shared set would have made all three as big as the sum);
- frame 135..143, glyphs 144..191 on SMS/GG (48 slots), 64 on the GB family;
- `shardlings_ui.write_all` refuses a base that leaves the SMS under 24 glyph
  slots. Keep the town under ~150 tiles.

What keeps the town small: every house shares ONE wall palette (wood) with its
own roof colour, windows are 16 px and tile-aligned so all houses reuse them,
and every texture repeats every 8 pixels (path speckles, roof shingles, pond
waves, floor boards).

### Doors, sills and the north exit

- A room holds at most **4 doors**, each an 8x16 rect. The player is 16 px wide
  and walking does not snap to a grid, so every doorway has a walkable SILL one
  tile wider than its frame (house: door column -1..+1; doormat: 4 columns with
  two door rects). Without it the player had to be pixel-exact.
- The town's north exit is a 4-wide `[[trigger]]` running `to_mossway`, not a
  door: the three houses use three of the four door slots.
- You arrive inside at (72, 112) and outside one row below the door.

### Sprites and effects

- `mom` and `clerk`: 96x16 sheets, six 16x16 frames (down, down, up, up,
  right, right; left is a flip). Every sprite PNG needs a `.sprites.toml`
  (the project uses 8x16 sprite mode).
- `emote_exclaim`: Wren's "!" bubble. It draws in sprite palette 0 (the
  player's), so it uses the skin and red shades.
- The kid has a `walk` animation and strolls (`kid_walk`, a looping thread).
- Pond: ONE animated tile index (every inner water cell shares it), 4 frames
  from `anim_water.png`, so the ripple costs no tile slots.
- The keystone glows by cycling palettes 34..36 into slot 3 (`glow_tick`).
- Tessel turns to evening after Wren is beaten: palettes 37..40 into slots 0..3.
- The title letters shimmer: palettes 1, 41, 42 into slot 1 (`title_glint`).

**Palette library indices are part of the scripts** (`palette_set pal = N`):
append new palettes at the END of `[[palette]]`, never insert or delete in the
middle, or remap every `pal =` in both script files.

### Text box and font

- `font.png` is a bold fixed-width 8x8 font (ASCII 32..127). Its paper is
  light grey, NOT white: a pixel with green above 249 counts as a
  variable-width marker, and a white sheet turned every space into zero width.
- `frame.png` is the 9-slice frame; the shell's `draw_frame` plots it and the
  box spans the full width with `lines + 2` rows. **18 characters fit on a
  line** inside the frame.
- `[scenes] letterbox` is on: on the SMS and PC Engine (bigger screens) the
  rooms are centred and the box sits on the room's bottom edge.

## Music

Nine songs, all four voices: melody (pulse, the driver's lead, which gets the
vibrato), harmony (second pulse), bass (wave), drums (noise). Every song sets
`gb_all_voices` (the GB's second pulse plays music; a sound effect briefly
takes it over) and `bass_priority` (a console with fewer voices keeps the bass
over the harmony).

| # | Song | Key, feel | Tempo (frames per 16th) | Lead | Harmony / bass / drums |
| :-: | --- | --- | --- | --- | --- |
| 0 | title | F major, hopeful, 4-bar intro | 7 | lead | arp16 / bounce / straight |
| 1 | town | C major, light swing, I-vi-ii-V | 8,8,5,5 (swung) | bright | stabs / walking (woody) / backbeat |
| 2 | route | A minor to C, adventurous | 6 | lead | arp8 / driving 8ths / rock |
| 3 | battle | E minor, chromatic riff | 5 | bright | fast arps / octave funk / busy |
| 4 | victory | C major fanfare, then a calm loop | 6 | bright | arp8 / bounce / light |
| 5 | home | G major waltz (3/4), lullaby | 9 | flute | oom-pah-pah / waltz / none |
| 6 | elder | D dorian, slow, mysterious | 8 | flute | the melody ECHOED 3 steps late / pedal / none |
| 7 | shop | Bb bossa | 7 | lead | bossa comping / root-fifth (woody) / rim groove |
| 8 | rival | G minor, heroic | 5 | bright | fast arps / octave funk / busy |

### How a song was written, step by step

1. **Fix the limits first.** Four voices (melody, harmony, bass, drums),
   which consoles drop which voice, about 5 KB per song, 4-bar patterns.
2. **Pick the mood and the style for the place.** The model was a cheerful,
   slightly jazzy 16-bit-era RPG sound: seventh chords, swing, catchy tunes,
   and a different flavour per place (a waltz at home, a bossa in the shop, a
   dorian mode for the mysterious Elder, a minor-key riff for battles).
3. **Tempo.** A step is a 16th note; frames per step = 3600 / (BPM x 4). 7
   frames is about 128 BPM, 5 about 180. The town's swing comes from uneven
   steps: 8+8 frames, then 5+5.
4. **Chords**, one or two per bar, from familiar progressions: I-vi-ii-V for
   the town, i-VI-III-VII for the route, ii-V-I turns for the shop, a pedal
   on D for the Elder. Each song is 16 bars (A + B sections of 8), the title
   adds a 4-bar intro.
5. **Melody**, bar by bar against the chords: chord tones on the strong
   beats, passing notes between them, a leap to the 7th or 9th for colour,
   phrases of two or four bars that answer each other, and a last bar that
   leads back into the first. Written as notes with lengths in steps:
   `E5:4` = E5 for 4 steps, `r:2` = silence, `_:2` = hold.
6. **The other three voices are arranged from the chords** by a named style,
   so a chord change is one edit:
   - harmony: `arp16` / `arp8` (chord tones cycling every step / every
     other step), `stab` (offbeat piano-like hits), `bossa` (comping on the
     bossa offbeats), `waltz` (beats 2 and 3), `pad` (a held guide tone),
     `echo` (the melody itself, 3 steps late and quiet). Chord tones are
     voiced between G4 and G5, under the melody;
   - bass: `walk` (root, third, fifth, then a chromatic step into the next
     bar's root), `bounce` (root, fifth, octave, fifth), `root8`, `drive`
     (octave-jumping 8ths), `pedal`, `bossa` (root and fifth on the bossa
     rhythm), `waltz` (root on beat 1);
   - drums: a 16-character pattern per song (`k` kick, `s` snare, `h` hat,
     `o` open hat, `r` rim, `.` rest), with a fill every 8th bar.
7. **Instruments** were designed after common hUGETracker practice: a warm
   square lead with a slow fade, a thinner bright lead, a swelling "flute"
   for the slow songs, a short pluck for arpeggios, a quiet echo voice, three
   wave tables for the bass (round triangle, punchy rounded square, stepped
   "upright" triangle), and pitched-noise drums.
8. **Rows are written** per step: the frame count, then note / instrument /
   volume for each voice. The effect column adds vibrato from the third step
   of a long melody note, a note cut for every rest, and the intro jump on the
   last row. The script checks that every bar adds up to 16 steps (12 for the
   waltz), every note is in range and every song fits its 16 KB chunk.
9. **Wiring**: each room's init script starts its song (see below).

Still to do: a listening pass in the emulator. Everything is built and fits
on all five consoles, but the songs have not been reviewed by ear yet.

Things that matter for this soundtrack:

- **Note numbers**: 1 = C3 .. 72 = B8. The wave channel sounds an OCTAVE BELOW
  the pulse for the same number, so bass is written in octave 3-4.
- **Envelope `decay`**: |7| is the FASTEST fade, |1| the slowest, 0 sustains,
  positive SWELLS (the `flute`). Easy to get backwards.
- **Drums are pitched noise**: each drum is its own instrument and its note
  sets the pitch (kick 21, snare 37, rim 45, open hat 49, hat 53).
- **Patterns are 4 bars (64 rows).** A song with an intro (title, victory)
  ends with effect 11 param 1, which jumps to pattern 1 and skips the intro on
  the way round; that effect counts in units of 64 rows.
- Interiors pick their song in `house_init` by `scene()`; the battle plays song
  8 when `trainer == 1` (Wren), else 3.
- Size: ~45 KB of song data (each song well under the 16 KB per-song limit).
  It moved the GB / GBC / SMS / GG ROMs from 512 KB to 1 MB.
- The PC Engine plays no music yet (its driver comes later); the songs build
  there and stay silent.

## Text: the dialogue library

Every line the game shows lives in `scripts/dialogue.toml` and the scripts use
`say` with a name. Names start with the speaker or place so they group in the
Dialogue dock: `mom_*`, `elder_*`, `kid_*`, `wren_*`, `shop_*`, `battle_*`.
Identical lines share one entry (`battle_critical_hit` serves five places).

Still plain `menu` events (a dialogue choice has no field for them): the title
menu (fixed row 12) and the four battle move menus (B backs out).

Keep every line at **18 characters or less** (the framed box); a `$var$`
counts at its widest value.

## Script facts other changes depend on

- Room indices and song indices as in the tables above.
- Party / progress variables: `pa_sp` (255 = no starter yet), `pa_lv`,
  `pa_hp`, `rv_sp` (Wren's species), `flags` bit 0 = Wren beaten, `trainer`
  (1 = the current battle is Wren), `gold`, `it_potion`, `it_shard`.
- Wren's spotting trigger (`wren_spot`) sits on the path rows 24-25 below him,
  clear of every tall-grass trigger (the player is in at most one trigger).
- The title script must not `lock`: a lock stops every other thread, and the
  logo shimmer is a thread. A timer does not fire while a menu holds the lock
  either, which is why the shimmer is a looping thread, not a timer.

## Capacity

- The emote pack, the emote art module and `uiframe` are in `[build]
  code_banks`; resident they overflowed bank 0 (GBC by 58 B, SMS/GG by ~430 B).
  Anything new in this project goes into `code_banks` first.
- Bank 0 spare after all of it: GBC ~2.4 KB, SMS ~0.7 KB, Game Gear ~0.8 KB.

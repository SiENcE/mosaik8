# vm-clipdemo

The reference proof of the **VM8 animation system** -- `lib/vm/clip.mos` (`vm.clip`)
driving `engine.anim` over studio `[animations]` clips lowered by `mosaik_anim.py`.

A single screen with a **player** and a **pacing enemy**, both animated through the
SAME reusable helper:

* the **player** (`vm.player.set_anim_external`) plays a flat idle / walk clip;
* the **enemy** (`vm.actor.set_anim_external`) paces left<->right and plays a
  directional walk clip whose LEFT facing is DERIVED from RIGHT via **`flip_left`**
  (hardware FLIP_X) -- the flip proof.

The game (`src/main.mos`) only computes each entity's STATE + FACING and calls
`clip.play(slot, state, facing)`; `vm.clip` owns `engine.anim` + the metasprite. The
clips are authored in the studio `[animations]` model (`studio.toml`, generated by
`assets/gen.py`) and lowered to `src/pclips.mos` (player) + `src/eclips.mos` (enemy).

It exists because the platformer port is WIDE (u16 coords + its own camera), so `vm.actor`
(u8 coords + `engine.camera`) can't live there -- this single-screen demo is where the
ACTOR animation path is proven.

## Build / verify

```
python projects/vm-clipdemo/assets/gen.py
python mosaik8.py build --platform gameboy projects/vm-clipdemo
python projects/vm-clipdemo/verify.py
```

Targets `gameboy` / `gameboy_color` (FLIP_X is a no-op on SMS/GG). PyBoy-verified: the
player's base tile cycles while walking, the enemy actor animates + paces across the
screen, and its OAM FLIP_X attribute bit toggles as it turns -- proving `vm.clip`,
`vm.actor` animation, and `flip_left` end to end.

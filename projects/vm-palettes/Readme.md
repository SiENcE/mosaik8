# vm-palettes

A VM8 game that uses every option of the studio's **Palettes** dock. Open it in
the studio and walk through the dock's tabs: everything below is already filled
in.

| Dock tab | What this world has |
|---|---|
| Library | 14 palettes: `ui` (made with **From tileset**) and 13 authored ones |
| Scene slots | `meadow` loads the **World default** rows; `cave` has its **own** background and sprite rows |
| Paint | a slot per tile in both rooms, slot 4 in the meadow and slots 4..6 in the cave, and a mossy stretch of the meadow's south wall painted cell by cell, which split the brick tile into `assets/tiles_split.png` |
| Sprites | the player has **per-cell** slots (head and body on two palettes); the villager and the gem have a whole-sprite **kind** slot |
| DMG | BGP `0xE4`, OBP0 `0xD0`, OBP1 `0xE0` |
| Consoles | the report: slots above 3 fold on SMS / Game Gear, the DMG shows no palettes |

Two runtime palette paths go beyond the dock: the gem's idle clip alternates its
**frame palette** (slot 3 and 4, the Animation dock), and walking **east** along
the meadow path writes the `night` palette into background slot 1 (`palette_set`,
`[world] pal_write`), walking **west** writes the grass back.

Not here: the dock's **16 colours** tab. A world is either this slot tier or the
16-colour tier (`vm-bkg16`, `pal-lab`).

Targets: Game Boy, Game Boy Color, Master System, Game Gear. On SMS / Game Gear
the sprites share one palette (their slot rides a per-room sheet upload, which
this project does not use). The PC Engine and Lynx are left out: a clip with a
frame palette trips a cc65 internal check (the same pre-existing failure as
`vm-palanim`), and the two-room game overflows both carts without it.

Generated by the studio repo's `tools/gen_samples/vm_palettes_world.py`
(delete-and-regenerate). `verify.py` checks the GBC ROM.
